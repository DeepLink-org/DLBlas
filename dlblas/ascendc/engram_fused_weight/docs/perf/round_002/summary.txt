--- Analysis ---
- Kernel launch overhead dominates (~5 us) for 512-element workload
- Scalar pipe dominates kernel internals (54.1% from Cast operations)
- Vector computation is negligible (1.6%)
- Operator is I/O and scalar-bound for small data, as expected
- Binary exact precision (max_diff=0) across all tested shapes

--- Fixed Issues ---
- DataCopy blockLen was using bytes instead of elements, causing data
  corruption for ubLoop >= 6. Fixed by using element count for blockLen.
- Remaining limitation: ubLoop >= 15 (dim0 > 28672) shows partial data
  corruption in last tile. This is beyond the design scope (default dim0=512)
  and is due to platform-level DMA descriptor limits on DAV_2201.
